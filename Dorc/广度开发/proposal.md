# SparkLearn 微信小程序重构需求文档

## 1. 背景与目标

本次需求面向 SparkLearn 微信小程序端，目标是基于现有后端能力重新构建一个轻量、聚焦、适合移动端学习场景的小程序前端。

本次不沿用旧小程序的信息架构与页面内容。旧小程序中的首页、知识图谱等入口不再出现在新版本中。小程序仅保留与本次目标相关的三类能力：多智能体对话辅助、刷题、个人中心。

## 2. 已确认约束

- 仅构建微信小程序前端页面。
- 后端不改动，完全复用现有后端接口能力。
- 不复用旧小程序页面内容。
- 旧小程序中首页、知识图谱等功能不出现在新版本中。
- 多智能体辅助功能使用 `/api/tutor` 相关能力，不使用 `/api/agent` 学习伙伴宠物化能力。
- AI 页面只做多智能体对话辅助，不做学习伙伴认养、成长、任务、宠物等内容。
- 刷题页只承载刷题主流程。
- 答题记录、统计、错题本、收藏题可放入个人中心。
- 刷题结果页允许提供 AI 辅助讲解入口。
- 视觉风格参考 `Dorc` 目录中的 UI/UX 相关文档。

## 3. 产品定位

新小程序定位为“移动端 AI 学习辅助与练习工具”，不是完整 LMS，也不是桌面端功能的全量迁移。

核心体验应围绕两个高频学习动作展开：

- 遇到问题时，进入 AI 助学，获得多角色、多视角解释。
- 需要巩固时，进入刷题，完成练习、判题和复盘。

个人中心用于承载学习数据、历史记录和学习画像，不抢占主流程注意力。

## 4. 信息架构

底部导航栏建议使用 3 个 Tab，按顺序为：

1. AI助学
2. 刷题
3. 我的

说明：

- `AI助学` 比 `AI界面` 更贴近用户任务，表达“用 AI 辅助学习”。
- `刷题` 比 `刷题界面` 更适合底部 Tab 文案，短、清晰、可扫读。
- `我的` 比 `个人中心页面` 更符合微信小程序常见语义。

如需严格保留用户原始表述，可改为：`AI界面 / 刷题界面 / 个人中心`，但推荐采用 `AI助学 / 刷题 / 我的`。

## 5. 页面范围

### 5.1 AI助学

目标：为学生提供多智能体辅助对话能力，支持围绕学习问题进行多角色讨论、可信回答和可追溯解释。

核心功能：

- 新建对话
- 查看对话列表
- 查看对话消息
- 选择或使用默认导师角色
- 输入问题并发送
- 开启多角色研讨模式
- 展示多智能体讨论过程
- 展示最终综合回答
- 展示可信度标识
- 展示引用来源
- 展示 MCP 工具调用过程，仅作为辅助信息展示
- 支持从刷题结果携带题目上下文进入 AI 讲解

推荐页面结构：

- 顶部：当前对话标题、角色入口
- 中部：消息流
- 多智能体过程区：以折叠面板展示阶段、角色发言、综合结论
- 底部：输入框、发送按钮、研讨模式开关

不包含：

- 学习伙伴认养
- 宠物形象
- XP、等级、成长任务
- `/api/agent` 搜索、总结、对比、推荐任务流

### 5.2 刷题

目标：提供轻量、高频的练习入口，让用户快速生成题目、作答、判题并获得反馈。

核心功能：

- 按主题生成题目
- 设置题目数量
- 支持单选题、多选题、填空题
- 提交答案
- 即时判题
- 展示正确答案
- 展示解析
- 展示知识点名称
- 收藏题目
- 错题后提供“问 AI”入口

推荐页面结构：

- 顶部：练习主题输入或选择区
- 中部：题目卡片
- 选项区：根据题型展示单选、多选或填空输入
- 底部：提交、下一题、收藏、问 AI

刷题页只处理当前练习体验。答题记录、统计、错题本、收藏题统一放入“我的”。

### 5.3 我的

目标：集中展示个人学习数据、复盘入口和设置能力。

核心功能：

- 学习画像
- 掌握度概览
- 答题统计
- 答题记录
- 错题本
- 收藏题
- 学习贡献日历
- 设置
- 账号信息

推荐页面结构：

- 顶部：用户信息与学习状态摘要
- 数据概览：正确率、累计答题、错题数、收藏数
- 学习画像：目标、基础水平、薄弱点、学习偏好
- 掌握度：知识点掌握度列表
- 复盘入口：答题记录、错题本、收藏题
- 设置入口

## 6. 视觉与交互规范

视觉风格参考 `Dorc/材料文档/SparkLearn-UIUX设计说明与视觉风格.md` 及相关 UI/UX 文档。

设计方向：

- 浅蓝科技感 + Apple Pure 克制风格
- 白色与浅灰蓝为主背景
- 主色使用蓝色，AI 功能可使用少量紫色
- 正确使用绿色，警告或中等置信度使用橙色，错误使用红色
- 页面信息层级控制在 3 层以内
- 移动端优先，避免桌面端复杂面板直接迁移
- 卡片圆角克制，避免过度装饰
- 使用图标辅助导航与操作，但不单独依赖图标传达含义
- 加载态使用骨架屏
- 空状态提供明确下一步操作
- 错误态提供重试入口

AI 回答需展示可信度：

- 高可信：绿色
- 中可信：橙色
- 低可信：红色

小程序端可用轻量化圆点、标签或小徽标呈现，不要求完全复刻桌面端 hover tooltip。

## 7. 后端接口映射

### 7.1 AI助学接口

使用 `/api/tutor` 相关接口：

| 功能 | 接口 |
| --- | --- |
| 获取导师角色 | `GET /api/tutor/roles` |
| 创建导师角色 | `POST /api/tutor/roles` |
| 获取对话列表 | `GET /api/tutor/conversations` |
| 创建对话 | `POST /api/tutor/conversations` |
| 更新对话 | `PUT /api/tutor/conversations/{conversation_id}` |
| 删除对话 | `DELETE /api/tutor/conversations/{conversation_id}` |
| 获取消息 | `GET /api/tutor/messages` |
| 发送消息 | `POST /api/tutor/chat` |
| 获取历史 | `GET /api/tutor/history` |

`POST /api/tutor/chat` 需要重点支持：

- `message`
- `conversation_id`
- `role_id`
- `workshop_enabled`
- `workshop_role_ids`
- `mcp_enabled`

前端需处理流式事件：

- `text`
- `meta`
- `confidence`
- `citations`
- `trust_meta`
- `workshop_meta`
- `workshop_phase`
- `hub`
- `mcp_call`
- `done`
- `error`

### 7.2 刷题接口

使用 `/api/quiz` 相关接口：

| 功能 | 接口 |
| --- | --- |
| 获取/生成题目 | `GET /api/quiz` |
| 提交答案 | `POST /api/quiz/submit` |
| 获取答题记录 | `GET /api/quiz/records` |
| 获取答题统计 | `GET /api/quiz/records/stats` |
| 删除答题记录 | `DELETE /api/quiz/records/{quiz_id}` |
| 获取错题 | `GET /api/quiz/wrong` |
| 删除错题 | `DELETE /api/quiz/wrong/{quiz_id}` |
| 获取收藏题 | `GET /api/quiz/favorites` |
| 设置收藏 | `POST /api/quiz/favorites` |

刷题页主要使用：

- `GET /api/quiz`
- `POST /api/quiz/submit`
- `POST /api/quiz/favorites`

个人中心使用：

- `GET /api/quiz/records`
- `GET /api/quiz/records/stats`
- `GET /api/quiz/wrong`
- `GET /api/quiz/favorites`

### 7.3 个人中心接口

使用学习画像与学习数据接口：

| 功能 | 接口 |
| --- | --- |
| 获取学习画像 | `GET /api/profile` |
| 更新学习画像 | `PUT /api/profile` |
| 画像初始化 | `POST /api/profile/onboarding` |
| 画像对话 | `POST /api/profile/chat` |
| 获取画像历史 | `GET /api/profile/history` |

说明：个人中心只展示与本次小程序核心体验相关的数据，不引入旧小程序的首页或知识图谱入口。

## 8. 关键流程

### 8.1 AI 多智能体辅助流程

1. 用户进入 `AI助学`。
2. 系统加载默认对话或创建新对话。
3. 用户输入学习问题。
4. 用户可开启多角色研讨模式。
5. 前端调用 `POST /api/tutor/chat`。
6. 前端解析流式事件并展示：
   - 阶段状态
   - 各角色发言
   - 最终回答
   - 可信度
   - 引用来源
   - MCP 调用记录
7. 回答完成后消息进入对话历史。

### 8.2 刷题流程

1. 用户进入 `刷题`。
2. 输入或选择练习主题。
3. 调用 `GET /api/quiz` 获取题目。
4. 用户作答。
5. 调用 `POST /api/quiz/submit` 判题。
6. 展示结果、解析、知识点。
7. 用户可收藏题目。
8. 若答错，用户可点击“问 AI”，携带题目、用户答案、正确答案和解析进入 `AI助学`。

### 8.3 个人复盘流程

1. 用户进入 `我的`。
2. 页面加载答题统计、画像、掌握度。
3. 用户进入答题记录、错题本或收藏题。
4. 用户可从错题详情跳转至 `AI助学` 继续追问。

## 9. 数据与状态要求

前端需维护：

- 当前 Tab
- 当前对话 ID
- 当前导师角色 ID
- 当前 AI 流式输出状态
- 当前题目集合
- 当前题目索引
- 当前作答结果
- 收藏状态
- 用户学习统计缓存

异常处理：

- 后端不可用时展示错误态和重试按钮。
- AI 流式中断时保留已输出内容，并提示可重试。
- 题目为空时展示空状态，引导重新生成。
- 个人中心数据为空时展示新用户引导。

## 10. 验收标准

信息架构验收：

- 底部导航只有 3 个 Tab。
- Tab 顺序为 `AI助学 / 刷题 / 我的`。
- 首页、知识图谱等旧入口不出现。
- 学习伙伴宠物化内容不出现。

AI 助学验收：

- 可发送学习问题。
- 可创建或使用默认对话。
- 可展示多智能体研讨过程。
- 可展示最终回答。
- 可展示可信度和引用来源。
- 刷题结果可跳转至 AI 讲解。

刷题验收：

- 可生成题目。
- 可完成单选、多选、填空作答。
- 可提交判题。
- 可查看答案解析。
- 可收藏题目。

个人中心验收：

- 可查看学习画像。
- 可查看答题统计。
- 可查看答题记录。
- 可查看错题本。
- 可查看收藏题。
- 可查看掌握度。
- 可进入设置。

技术验收：

- 不修改后端接口。
- 前端所有业务数据来自现有后端。
- 小程序页面适配移动端。
- 关键接口失败时有明确错误提示。
- AI 流式输出有加载态、完成态和错误态。

## 11. 不在本期范围

- 后端改造
- 新增后端接口
- 桌面端或 Web 端改造
- 教师端
- 管理端
- 学习社区
- 资源生成
- 知识图谱页面
- 学习伙伴宠物系统
- `/api/agent` 任务系统
- 视频、PPT、语音等多媒体生成能力

## 12. 待实现建议

优先级建议：

1. 先完成三 Tab 信息架构与基础路由。
2. 再完成刷题闭环，因为接口清晰、验证成本低。
3. 再完成 AI 助学基础对话。
4. 最后增强多智能体研讨过程、可信度、引用、MCP 调用展示。
5. 个人中心穿插实现，优先展示答题统计、错题本和收藏题。

交互建议：

- AI 页面默认进入最近一次对话。
- 刷题页面默认提供“Python 基础”主题，但允许用户修改。
- 错题详情中的“问 AI”应自动构造上下文，用户无需重新复制题目。
- 个人中心不做复杂仪表盘，优先使用轻量卡片和列表。
