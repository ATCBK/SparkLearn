# SparkLearn 测试验证与项目可交付说明

## 1. 文档定位

本文档说明 SparkLearn 的测试策略、验证范围、关键测试命令、已验证能力、交付物和后续风险控制。该文档可用于答辩、验收和项目交付材料。

## 2. 测试目标

SparkLearn 的测试目标包括：

- 验证核心学习闭环可运行。
- 验证前后端接口契约稳定。
- 验证 Tutor SSE 流式交互正常。
- 验证 A2UI / AG-UI 事件可以生成和恢复。
- 验证资源生成、预览、下载和兜底逻辑。
- 验证 RAG、记忆、可信回答链路不阻断主流程。
- 验证教师端、社区端、桌面端、小程序端关键入口可用。

## 15. 已知风险与控制

| 风险 | 控制策略 |
| --- | --- |
| 外部 AI 服务不稳定 | 模板兜底、错误事件、重试 |
| SSE 连接中断 | 保留已输出内容，允许重试 |
| PostgreSQL 配置错误 | 健康检查和启动日志 |
| 小程序流式能力差异 | 降级为完成后展示 |
| MCP 本地命令风险 | Web 端限制 stdio，桌面端承接 |
| 资源预览失败 | 回退展示正文或明确错误 |
| 知识证据不足 | 低可信提示，不伪造引用 |

## 17. 交付验收的“可陈述指标”

### 17.1 通过标准（可在答辩现场口头说明）

- Tutor 会话可稳定输出流式文本，并在 3 秒内至少返回一次 `meta`/`progress`。
- `/api/resources/generate` 发生上游故障时，前端仍能保留已生成内容并触发可重试。
- `/api/memory/inject-context` 可在上下文不足时返回基础画像，不导致 500。
- `/api/info-stream/recommendations` 单一来源超时不影响全局返回。
- `/api/video/jobs/{job_id}/events` 任务不存在时返回 `VIDEO_JOB_NOT_FOUND` 且无假结果。
- `/api/mcp/services/{service_id}/call` stdio 与 HTTP 两种模式可切换，测试失败仅影响对应服务。
- `/api/auth/*` 登录链路在验证码超时场景能触发准确错误码。

### 17.2 缺陷闭环

每个功能域都绑定“检测-分析-修复-复测”：

- 发现：测试、日志、用户反馈。  
- 归类：接口异常、SSE异常、资源异常、外部服务异常。  
- 修复：加兜底、添加重试、降级到保守响应。  
- 复测：回归一次关键交互，确认不影响主流程。  

最终目标是：出现异常也能给出“可解释、可恢复”的反馈，而不是直接中断学习流程。
