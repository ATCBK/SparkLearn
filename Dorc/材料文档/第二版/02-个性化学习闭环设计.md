# 个性化学习闭环设计（第二版）

## 1. 闭环定义
SparkLearn 的学习闭环不是“问答即止”，而是持续收敛的一次迭代流：

1. 用户画像建立/更新：`/api/profile`
2. 路径生成与建议：`/api/learning-path`
3. 任务下发与执行：`/api/tasks`
4. 评测反馈：`/api/quiz`
5. 画像回灌：`/api/memory` 与 tutor 的 `update_memory_from_turn`

## 2. 关键接口与流程

### 2.1 学生画像
- `POST /api/profile/onboarding`：新用户创建基础画像。
- `POST /api/profile/initiate`：触发初始化画像流程。
- `GET /api/profile`：读取当前画像。
- `PUT /api/profile`：更新画像字段（`goals`、`knowledge_level`、`weak_points` 等）。
- `GET /api/profile/history`：画像历史版本。
- `POST /api/profile/history/analyze`：画像变更趋势分析。

### 2.2 学习路径
- `POST /api/learning-path`：生成初始路径，返回阶段、节点、优先级。
- `GET /api/learning-path/history`：学习路径历史。
- `POST /api/learning-path/node-suggestions`：按单节点细化建议。
- `GET /api/learning-path/{path_id}`：按 id 查路径详情。

### 2.3 学习任务
- `GET /api/learning-path`：获取当前路径。
- `GET /api/tasks/today`：今天任务。
- `POST /api/tasks`：新增任务。
- `PUT /api/tasks/{task_id}/complete`：任务完成。
- `DELETE /api/tasks/{task_id}`：删除任务。

### 2.4 评估和掌握度
- `/api/quiz`：题库与练习、错题与收藏。
- `/api/mastery`：掌握度明细。
- `/api/contribution`：学习贡献统计。
- `/api/dashboard/stats`：看板总览（完成率、学习时长、准确率）。

## 3. 数据流（每轮学习）

1. 用户打开页面时请求 `/api/profile`，前端渲染个性化参数。
2. 用户发起学习咨询：Tutor 请求携带 `pageContext`（profile + generated_resources + 学习备注）。
3. Tutor 在生成回答前先构建 context，可能触发知识库检索。
4. 回答完成后，后端执行：
   - 生成 assistant message 落库到 `tutor_messages`
   - 更新 `memory`：`working/episodic` 与 `semantic` 的回写
   - 记录 `learning_events.jsonl`。
5. 前端在主页刷新学习任务与资源区：
   - `/api/tasks/today`
   - `/api/resources`
   - `/api/contribution`

## 4. 关键异常与兜底

- 画像缺失：请求 `/api/profile` 失败时，按默认画像继续对话并标记 `open_mode`。
- 任务执行失败：前端显示“任务重试/改为待办”按钮，后端接受幂等更新。
- 学习路径生成失败：可直接使用模板化路径（基于 `path_type: basic`）返回，确保咨询链路不中断。

## 5. 如何体现答辩价值
- 强调“系统不是回答器”，而是**行为闭环系统**。
- 所有动作都有落盘动作和时间戳：会话、任务、练习、评分、画像。
- 给出一个典型指标闭环：弱点识别 -> 路径调整 -> 任务完成率上升 -> 画像更新。
