# SparkLearn 记忆系统与学习数据流转

## 1. 文档定位

本文档说明 SparkLearn 的数据流转、学习事件、画像快照、多层记忆系统和上下文注入机制。该文档可用于解释项目如何做到多轮连续学习、个性化持续更新和学习数据闭环。

## 2. 设计原则

SparkLearn 的数据层遵循以下原则：

- 事实数据和智能理解解耦。
- 用户行为以事件形式记录。
- 学习画像以结构化字段维护。
- 记忆系统负责给智能体提供上下文。
- 回答、练习、资源和路径结果都能反哺画像。
- PostgreSQL 保存核心业务数据，文件和生成物保存到资源目录并由元数据索引。

## 3. 数据流转总览

典型数据流：

```text
前端行为
  -> FastAPI 路由
  -> PostgreSQL 事实数据
  -> 学习事件记录
  -> 画像快照更新
  -> 记忆写入/检索/整合
  -> Agent 上下文注入
  -> AI 输出
  -> 消息/资源/报告写回
```

## 4. 学习事件

### 4.1 事件来源

事件来源包括：

- 画像建档。
- 任务创建和完成。
- 路径调整。
- 资源生成和使用。
- Tutor 对话。
- 文件上传和网页采集。
- 知识库检索。
- 练习提交。
- 错题和收藏。
- 教师诊断和广播。
- 社区互动。

### 4.2 事件结构

```json
{
  "event_id": "evt_001",
  "user_id": "single_user",
  "type": "quiz_submitted",
  "created_at": "2026-07-07T10:00:00",
  "payload": {
    "quiz_id": "q_001",
    "chapter": "Python 函数",
    "correct": false,
    "knowledge_point": "参数传递"
  }
}
```

### 4.3 事件用途

- 更新学习进度。
- 计算掌握度。
- 识别薄弱点。
- 生成报告。
- 触发路径调整。
- 写入语义记忆。

## 5. 画像快照

画像快照是智能体读取个性化上下文的快速入口。它来自 PostgreSQL 中的画像字段，并结合最近行为形成摘要。

典型内容：

```json
{
  "user_id": "single_user",
  "profile": {
    "stage": "基础巩固",
    "weak_points": ["数据库", "函数"],
    "preference": ["案例驱动"],
    "daily_time": 60
  },
  "recent_behavior": {
    "accuracy": 0.72,
    "recent_wrong_points": ["参数传递"],
    "resource_preference": ["video", "code"]
  }
}
```

用途：

- Tutor 回答个性化。
- A2UI 任务卡依据。
- 路径规划输入。
- 教师诊断输入。
- 资源生成风格控制。

## 6. 四层记忆模型

### 6.1 working memory

工作记忆保存当前会话或当前任务的短期上下文，例如：

- 当前用户问题。
- 当前文件上下文。
- 当前工具结果。
- 当前生成任务状态。

特点：

- 生命周期短。
- 优先用于当前回答。
- 不一定长期保存。

### 6.2 episodic memory

情节记忆保存学习经历，例如：

- 用户曾经在哪个知识点卡住。
- 用户完成过哪个项目任务。
- 用户在某次对话中表达了目标变化。

用途：

- 支持连续追踪。
- 在后续对话中引用学习经历。

### 6.3 semantic memory

语义记忆保存稳定的个性化事实，例如：

- 学习目标。
- 长期薄弱点。
- 偏好的讲解方式。
- 对某类资源的偏好。

用途：

- 画像增强。
- 长期个性化。
- 多轮 Tutor 上下文注入。

### 6.4 perceptual memory

感知记忆保存与资料、视频、界面状态相关的上下文，例如：

- 当前视频脚本。
- 当前上传资料摘要。
- 当前网页资料摘要。
- 当前页面上下文。

用途：

- 数字人视频问答。
- 文件问答。
- 网页资料讲解。

## 7. 记忆接口

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/memory` | GET | 获取记忆概览 |
| `/api/memory/profile/{user_id}` | GET | 获取用户画像记忆 |
| `/api/memory/add` | POST | 新增记忆 |
| `/api/memory/search` | POST | 搜索记忆 |
| `/api/memory/inject-context` | POST | 构造上下文注入 |
| `/api/memory/consolidate` | POST | 整合记忆 |
| `/api/memory/forget` | POST | 遗忘记忆 |
| `/api/memory/profile` | PUT | 更新画像记忆 |

### 7.1 新增记忆请求

```json
{
  "user_id": "single_user",
  "layer": "semantic",
  "content": "用户更偏好通过项目案例学习后端接口",
  "tags": ["learning_preference", "backend"],
  "importance": 0.8,
  "confidence": 0.9
}
```

### 7.2 记忆搜索响应

```json
{
  "items": [
    {
      "id": "mem_001",
      "layer": "semantic",
      "content": "用户更偏好通过项目案例学习后端接口",
      "score": 0.84,
      "importance": 0.8,
      "confidence": 0.9
    }
  ]
}
```

## 8. 上下文注入

### 8.1 注入内容

Agent 上下文通常包含：

- 用户画像摘要。
- 近期学习行为。
- 相关记忆。
- 当前资料上下文。
- 知识库证据。
- 工具调用结果。
- 当前页面上下文。

### 8.2 注入示例

```text
学习者画像：
- 阶段：基础巩固
- 薄弱点：数据库建模、接口设计
- 偏好：案例驱动、图文讲解
- 每日时间：60 分钟

相关记忆：
- 用户曾多次询问 FastAPI 路由拆分问题。
- 用户更喜欢通过项目案例理解数据库。

当前资料：
- 上传文件《FastAPI 入门》提到 APIRouter 的模块化用法。
```

## 9. 记忆更新机制

记忆更新触发点：

| 触发点 | 写入层 |
| --- | --- |
| Tutor 对话中的稳定偏好 | semantic |
| 一次具体学习经历 | episodic |
| 当前文件/视频上下文 | perceptual |
| 当前会话短期信息 | working |
| 练习错因重复出现 | semantic + episodic |

更新策略：

- 对短文本提取关键事实。
- 对重复事实提升重要性。
- 对矛盾事实保留最新版本并降低旧事实置信度。
- 对低价值临时信息定期遗忘。

## 10. 数字人视频记忆

数字人场景使用视频脚本作为短期知识上下文。

相关接口：

- `POST /api/num-person/memory/load`
- `POST /api/num-person/chat`
- `GET /api/num-person/memory/{memory_id}`
- `DELETE /api/num-person/memory/{memory_id}`

流程：

1. 用户选择视频。
2. 后端加载视频脚本并分段。
3. 建立视频记忆。
4. 用户提问时，系统从当前视频记忆中检索片段。
5. 数字人基于视频内容回答。
6. 用户切换视频时清除旧记忆并加载新记忆。

## 11. 兜底策略

| 场景 | 兜底 |
| --- | --- |
| 画像不存在 | 创建默认画像 |
| 记忆文件或记录缺失 | 初始化空记忆结构 |
| 记忆搜索无结果 | 只使用画像和当前问题 |
| 向量检索失败 | 使用字符重叠或关键词匹配 |
| 记忆内容异常 | 清洗字段并跳过坏记录 |
| 视频记忆过期 | 提示重新加载当前视频 |
| 上下文过长 | 按重要性、置信度和相关性裁剪 |

## 12. 材料可复用表达

SparkLearn 的记忆系统让 AI 辅导具备连续性。系统通过学习事件记录用户行为，通过画像快照描述当前状态，通过 working、episodic、semantic、perceptual 四层记忆保存不同粒度的上下文，并在 Tutor、路径规划、资源生成和数字人问答中动态注入，从而实现持续个性化。

## 13. 端到端答辩要点（可直接复述）

### 13.1 接口契约汇总

| 分类 | 关键请求 | 响应形态 | 兜底行为 |
| --- | --- | --- | --- |
| 查询记忆 | `GET /api/memory` | `layers` + `profile_snapshot` + `memory_stats` | 找不到用户时返回空记忆结构 |
| 写入记忆 | `POST /api/memory/add` | `success + mem` | 超长文本截断、重复去重、字段标准化 |
| 检索记忆 | `POST /api/memory/search` | `items[]`（含 score/importance/confidence） | 无结果返回空数组，不中断主流程 |
| 注入上下文 | `POST /api/memory/inject-context` | `context_text` | 无画像时仅返回文件+问题上下文 |
| 记忆整合 | `POST /api/memory/consolidate` | `updated_counts` | 失败只回退轻量摘要 |
| 记忆遗忘 | `POST /api/memory/forget` | `deleted_count` | 不存在记录返回 200 及 0 |
| 数字人内存 | `POST /api/num-person/memory/load` | `memory_id` + `timeline_meta` | 失败返回明确 `NP_MEMORY_NOT_FOUND` |
| 数字人对话 | `POST /api/num-person/chat`（SSE） | `token/done/error` | 触发过期则强制要求重新加载 |

### 13.2 前端交互与错误闭环

1. 学习页面展示画像/目标标签前，先调用 `/api/memory/profile/{user_id}` 和 `/api/memory`，失败时不阻塞主要页面。
2. Tutor/路径规划/资源建议请求统一附带 `top_k` 上下文参数，后端返回 `context` 后再发起 LLM/策略请求。
3. 任何记忆相关返回错误都不会阻断 `/api/tutor/chat`，只会在提示中标记“已按基础画像回答”，并降低可信度展示。
4. 记录失败、查询超时、合并失败，统一通过 `detail` 或 `memory_error` 字段返回并在前端显示重试按钮。

### 13.3 风险说明（材料中可直接说）

- 风险点：记忆质量高低直接影响建议准确性。
- 控制点：分层记忆+版本号+重要性衰减+字段清洗，避免陈旧脏数据长期影响决策。
- 亮点：同一会话既有短期工作记忆（working），也有长周期语义记忆（semantic），满足“短期连续 + 长期个性化”的双目标。
