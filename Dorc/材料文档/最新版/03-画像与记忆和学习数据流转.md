# 03 画像与记忆和学习数据流转
文档状态：已完成
版本口径：当前代码实现（2026-07-08）
写作口径：仅记录系统基础信息、功能实现、接口、数据流和存储设计。

## 1. 用户画像数据结构
- `students` 保存用户基础信息，包括 user_id、name、email、major、grade、phone、avatar、last_login_at 等。
- `profiles` 保存学习画像，包括 goal、knowledge_level、weak_points、learning_preference、cognitive_style、daily_time、practical_ability、current_stage、version、updated_at。
- 画像字段中的列表类数据以 JSON 文本保存，便于在 SQLite 和 PostgreSQL 之间保持兼容。

## 2. 画像建立流程
1. 问卷建档接收结构化表单，直接映射到画像字段。
2. 对话建档先创建引导问题，再通过多轮问答提取学习目标和偏好。
3. 手动编辑允许用户直接修改画像字段。
4. 每次画像写入都会更新 version 和 updated_at。

## 3. 画像更新机制
- 练习提交后更新知识点掌握度，并影响后续路径和任务建议。
- 学习任务完成后写入贡献记录和学习事件。
- Tutor 对话和历史分析可以补充用户当前问题、薄弱点和学习偏好。
- 资源学习记录用于判断用户关注的主题、资源类型和内容难度。

## 4. 记忆系统结构
- 短期记忆保存当前对话、当前任务和本轮上下文。
- 中期记忆保存近期学习事件、练习结果、资源使用和会话摘要。
- 长期记忆保存用户画像、目标、偏好、薄弱点、历史掌握度和重要学习事实。
- 记忆模块通过 `/api/memory/*` 提供新增、搜索、注入上下文、整合和遗忘能力。

## 5. 学习事件数据
- 学习事件用于记录用户在系统中的关键行为。
- 事件来源包括画像建档、任务完成、练习提交、资源生成、资源学习、Tutor 对话和路径调整。
- 事件数据用于生成报告、更新记忆、分析学习趋势和调整路径。

## 6. 练习结果流转
1. 用户从 quiz 接口获取题目。
2. 用户提交答案后，后端判断正确性并返回解析。
3. 提交结果写入练习记录。
4. 答错题目进入错题数据。
5. 收藏题目进入收藏数据。
6. 对应知识点的 mastery_records 分数被更新。

## 7. 资源学习数据流转
- 资源生成后写入资源索引和文件目录。
- 资源预览、下载、质量评价和代码评价形成资源使用数据。
- 资源主题、类型、质量结果和学习行为可被后续推荐和画像更新使用。

## 8. Tutor 对话数据流转
- 会话写入 `tutor_conversations`。
- 消息写入 `tutor_messages`。
- 上传或采集的文件写入 `tutor_files`。
- 文件切片写入 `tutor_file_chunks`。
- 后续对话会读取这些数据作为上下文。

## 9. 数智人记忆数据
- 数智人模块提供记忆加载、聊天、查看和删除接口。
- 记忆加载用于把已有学习数据导入数智人上下文。
- 聊天接口使用数智人记忆生成个性化回答。
- 查看和删除接口用于管理指定 memory_id 的记录。

## 10. 数据读写位置
- 数据库：students、profiles、mastery_records、contribution_days、tutor_*、knowledge_*、agent_* 等表。
- 用户目录：`backend/data/users/{user_id}` 保存用户级 JSON、JSONL、资源记录或事件文件。
- 资源目录：保存生成资源、上传资料、视频产物、字幕、音频和可下载文件。
