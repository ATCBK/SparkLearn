# SparkLearn 网页端缩放适配设计

## 1. 背景

SparkLearn 前端当前主要通过浏览器视口宽度决定布局。学习端桌面外壳还会固定占用 220px 侧栏，因此页面断点判断所依据的宽度与实际内容区宽度不一致。在不同电脑分辨率或浏览器缩放比例下，部分多栏页面、固定宽度面板、表格、甘特图和图谱会发生挤压、遮挡、裁切或非预期地切换成移动布局。

本次改造覆盖学习端、教师端、管理端、Tutor、登录、引导、学习广场及共享页面，目标是在电脑浏览器缩放 67%～200% 时保持桌面布局和视觉比例，不通过整页 `transform: scale()` 或 CSS `zoom` 模拟缩放。

## 2. 已确认目标

- 电脑端在浏览器缩放 67%、80%、100%、125%、150%、175%、200% 时保持桌面布局。
- 缩放过程中不得自动切换为移动端顶部栏、底部导航或单栏移动版结构。
- 文字不得重叠、竖排、被不可恢复地裁切。
- 图片、视频、头像、背景图和图表不得被非等比拉伸。
- 可用宽度不足时允许出现横向滚动。
- 普通页面优先使用页面级横向滚动；复杂数据区域优先使用局部横向滚动。
- 弹窗、下拉菜单、浮层、固定导航和 AI 助手在滚动与缩放后仍可操作。
- 原有手机访问能力保留，但“电脑高倍缩放”和“真实手机设备”不能仅依赖视口宽度进行同一种判断。

## 3. 不采用的方案

### 3.1 整页 CSS 缩放

不使用 `zoom` 或 `transform: scale()` 缩放整个应用。该方式容易造成文字模糊、点击热区偏移、固定定位与弹窗坐标异常，也会削弱浏览器原生缩放的可访问性。

### 3.2 高倍缩放自动切换移动版

不以 `window.innerWidth` 或单纯的 `max-width` 媒体查询作为电脑端布局模式的唯一依据。浏览器放大后 CSS 视口会变窄，单纯依赖视口会错误切换移动导航和移动页面结构。

## 4. 总体架构

### 4.1 设备布局模式

新增统一的布局模式判断，区分：

- `desktop`：电脑设备，始终使用桌面外壳和桌面页面结构。
- `mobile`：真实移动设备，继续使用现有移动外壳。

判断应综合稳定设备信息与交互能力，例如屏幕尺寸、主指针精度和悬停能力，并允许服务端首屏使用安全默认值，避免 hydration 不一致。窗口宽度仍可用于计算滚动和可用空间，但不再单独决定电脑是否切换移动版。

布局模式通过应用根节点的稳定属性向下传递，例如 `data-layout-mode="desktop"`，供公共样式、页面容器和测试使用。

### 4.2 桌面工作画布

桌面模式下，各业务外壳提供统一的最小工作宽度：

- 学习端：包含侧栏、顶部栏和主内容区。
- 教师端、管理端：包含固定侧栏与主内容区。
- Tutor：包含左侧导航、会话列表、主工作区及可选右侧面板。
- 登录、引导、广场、共享页：使用各自外壳，但遵守相同的桌面最小宽度规则。

当浏览器高倍放大导致可视区域小于工作画布时，由明确的滚动容器承载横向滚动，避免内容被 `overflow: hidden` 截断。固定侧栏与顶部栏的定位需要和滚动容器协同，确保导航始终可达，主内容的最左侧和最右侧均能滚动查看。

最小宽度不使用一个覆盖所有页面的任意常量，而是按外壳确定基线，并通过 CSS 变量统一管理，避免页面各自写死不同值。

### 4.3 页面响应规则

现有页面中的 `max-width` 媒体断点按用途分类处理：

1. 决定移动版与桌面版结构的断点，改为基于布局模式。
2. 仅用于桌面内容区优化的断点，改为容器查询或外壳级状态。
3. 复杂组件保持固定桌面结构，在自身容器内启用滚动。
4. 纯装饰性间距和字号可继续使用流式值，但不得改变核心桌面信息架构。

不进行无关的视觉重设计，也不改变业务功能和数据流。

## 5. 组件级策略

### 5.1 导航与外壳

- 学习端 `Sidebar`、`Topbar` 和主内容区共享桌面画布宽度变量。
- 教师端与管理端固定侧栏采用相同的桌面模式判定和滚动约束。
- Tutor 独立页面保留多面板结构；不足宽度时由外层画布滚动，不隐藏关键面板。
- 广场侧栏、登录双栏和引导页在电脑端缩放时保持桌面结构。
- 手机设备继续使用原有移动导航，不受桌面最小画布影响。

### 5.2 表格与数据列表

- 表格外层统一添加可聚焦的横向滚动容器。
- 表头与数据列设置符合内容的最小宽度，禁止通过压缩造成文字逐字换行。
- 操作列保持可达，必要时采用局部粘性定位，但不遮挡数据列。

### 5.3 甘特图、知识图谱和可视化图表

- 甘特图和图谱使用独立的最小画布及双向滚动。
- ECharts 或基于 Canvas/SVG 的图表在容器尺寸变化后调用 `resize` 或等价逻辑。
- SVG 使用 `viewBox` 保持比例，不同时强制不相容的固定宽高。
- 全屏模式和侧边详情面板不得依赖未经扣除的 `100vw`。

### 5.4 图片、视频和背景

- 内容图片使用 `max-width: 100%`、明确的 `aspect-ratio` 和合适的 `object-fit`。
- 头像、Logo 等不可裁切资源使用 `object-fit: contain`。
- 封面和装饰背景可使用 `cover`，但不得改变内容图片比例。
- iframe、视频和预览区域设置明确的宽高比或最小画布，并由容器承载滚动。

### 5.5 弹窗与浮层

- 弹窗最大尺寸同时受桌面画布和当前可视区域约束。
- 弹窗内容区允许内部滚动，关闭按钮和主要操作始终可见。
- 下拉菜单、AI 助手、学习笔记面板等 fixed/absolute 元素需要验证缩放后的锚点、层级和可达性。

## 6. 溢出与错误处理

- 禁止在应用根节点使用会吞掉内容的全局 `overflow-x: hidden`。
- 每个横向滚动区域必须有清晰边界，避免页面滚动与组件滚动相互抢夺。
- 长文本使用合理换行；代码、URL、标识符等不可自然换行内容允许局部滚动或断词。
- JavaScript 布局检测失败时，电脑端采用桌面安全默认值，移动端可在客户端挂载后校正。
- `ResizeObserver` 等浏览器能力不可用时，图表至少在窗口 `resize` 时更新。

## 7. 测试设计

### 7.1 自动化缩放测试

新增 Playwright 响应式回归测试。测试通过浏览器上下文或 DevTools 能力设置缩放效果，并覆盖：

- 缩放比例：67%、80%、100%、125%、150%、175%、200%。
- 基础分辨率：1024×768、1280×720、1366×768、1440×900、1920×1080。
- 浏览器：Chromium；本地人工补充 Chrome 与 Edge 验收。
- 页面范围：学习端、教师端、管理端、Tutor、登录、引导、广场、共享页的代表性和高风险页面。

### 7.2 自动断言

每个页面至少验证：

- 电脑端仍为 `desktop` 布局模式。
- 桌面侧栏或桌面导航存在，移动底部导航不存在。
- 文档和指定滚动容器的溢出符合预期，不存在不可达的负方向溢出。
- 关键标题、主要按钮、导航入口和关闭按钮可见且可点击。
- 图片和视频的实际宽高比与声明宽高比相符。
- 关键文本元素没有相互覆盖。
- 控制台无新增布局相关异常。

表格、甘特图、图谱、弹窗和浮层增加专项交互断言。

### 7.3 视觉回归与人工验收

- 在关键缩放档位保存全页或关键区域截图。
- 对首页、路径、报告、资源生成、Tutor、教师仪表盘、管理仪表盘、登录和引导页进行截图比较。
- 人工检查浏览器缩放菜单的真实 67%～200% 行为，确认文字清晰、图片不变形、滚动可达。

## 8. 实施顺序

1. 先编写能够复现电脑缩放错误切换和不可控溢出的失败测试。
2. 实现统一布局模式与桌面画布基础设施。
3. 改造学习端、教师端、管理端和 Tutor 外壳。
4. 按高风险组件顺序处理表格、甘特图、图谱、图表、弹窗和浮层。
5. 扫描并修正其余页面的固定尺寸和断点。
6. 执行 lint、TypeScript/Next.js 构建、既有 Playwright 测试和新增缩放矩阵测试。
7. 进行 Chrome/Edge 人工缩放验收并记录结果。

## 9. 完成标准

- 全站在电脑浏览器 67%～200% 缩放范围保持桌面布局。
- 所有纳入测试的页面无文字重叠、不可恢复裁切或媒体拉伸失真。
- 空间不足时滚动行为明确，导航、主要内容和操作按钮均可到达。
- 真实手机访问仍使用移动布局。
- lint、构建、既有关键测试和新增缩放测试通过。
- 不引入与缩放适配无关的业务或视觉变更。
