# 安全政策

## 报告安全漏洞

如果您发现安全漏洞，请**不要**通过公开的 Issue 报告。请按照以下步骤操作：

### 1. 私下报告

请通过以下方式私下报告安全漏洞：

- **Email**: [security@example.com]
- **GitHub Security Advisories**: 使用 GitHub 的安全报告功能

### 2. 报告内容

请包含以下信息：

- 漏洞类型
- 漏洞的详细描述
- 复现步骤
- 潜在影响
- 建议的修复方案（如果有）

### 3. 响应时间

我们承诺：

- **24 小时内**：确认收到报告
- **72 小时内**：提供初步评估
- **7 天内**：提供详细的修复计划
- **30 天内**：发布修复版本

## 安全最佳实践

### 对于开发者

1. **依赖管理**
   - 定期更新依赖包
   - 使用 `npm audit` 检查已知漏洞
   - 避免使用不信任的依赖

2. **代码安全**
   - 避免硬编码敏感信息
   - 使用环境变量存储配置
   - 实施输入验证
   - 防止 XSS 和注入攻击

3. **数据安全**
   - 加密敏感数据
   - 使用 HTTPS
   - 实施访问控制
   - 定期备份数据

### 对于用户

1. **账户安全**
   - 使用强密码
   - 启用两因素认证
   - 定期更改密码

2. **应用安全**
   - 及时更新应用
   - 不要安装未知来源的应用
   - 注意权限请求

## 安全工具

### 依赖检查

```bash
# 检查已知漏洞
npm audit

# 自动修复漏洞
npm audit fix
```

### 代码扫描

```bash
# ESLint 安全规则
npm run lint

# TypeScript 类型检查
npm run type-check
```
