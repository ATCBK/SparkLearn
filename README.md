## 项目愿景

高等教育与职业学习正面临同一个核心问题：学习者基础、节奏、目标差异巨大，但资源供给与辅导路径往往标准化。

SparkLearn 通过 AI 多智能体协同，为学习者构建一套可持续优化的个性化学习闭环：

**画像构建 → 路径规划 → 资源生成 → 学习互动 → 练习评测 → 反馈报告 → 画像更新**

平台目标不是“单点工具”，而是形成“可持续演进的学习系统”。

## 当前版本更新

### 多用户演示与真实注册规划

当前新增一条多用户改造分支，目标是同时满足“评审秒看完整能力”和“真实新用户从 0 开始使用”两种场景。

- 登录注册将支持两种方式：手机号 + 密码登录、手机号 + 验证码登录。注册时需要填写验证码、昵称、密码和确认密码，后端保存密码哈希，不保存明文密码。
- 演示账号使用固定手机号 + 密码登录，登录后直接进入完整演示空间，展示已有学习画像、路径、资源、练习、报告、Tutor 对话、知识库等平台能力。
- 演示账号可通过环境变量初始化：`DEMO_USER_PHONE=演示手机号`、`DEMO_USER_PASSWORD=演示密码`、`DEMO_USER_ID=demo_user`。后端启动时会自动创建或更新该账号，并复制 `single_user` 的演示画像和关键学习数据。
- 真实新用户使用自己的手机号注册后进入独立用户空间，不读取演示数据。首次登录进入画像采集流程，完成后再生成属于该用户的学习路径与推荐内容。
- 资源库、知识库、练习、报告、导师对话等模块在真实新用户没有数据时展示空状态：轻量矢量插画、简短说明和明确行动按钮，避免空白页面或假数据。
- 后端将逐步把 `single_user` 兼容读写改为基于当前 JWT 用户的 `user_id` 隔离读写，优先改造学生端 profile、learning、resources、quiz、knowledge、tutor 主链路。

详细设计见 `docs/superpowers/specs/2026-07-16-multi-user-demo-auth-design.md`。

### 服务器上线与资源约束

当前部署分支补齐了小内存服务器上线约束，目标是在保留演示账号历史数据的前提下，把无用缓存压缩到最低，并让真实新用户仍然进入空状态。

- 服务器数据必须保留：`/opt/sparklearn/app/data` 和 `/opt/sparklearn/uploads` 属于业务数据与演示数据，部署前必须备份，不得清理。
- 小内存优化以清理缓存为主：Docker build cache、apt cache、过大日志可以清理；数据库、上传文件、`.env.deploy`、当前 compose 配置不得覆盖。
- 后端镜像内置 FFmpeg：`Dockerfile.backend` 安装 `ffmpeg`，并设置 `FFMPEG_PATH=/usr/bin/ffmpeg`，用于本地视频合成。
- 线上环境关闭单用户绕过：`ALLOW_SINGLE_USER_BYPASS=false`，所有学生端数据必须按当前登录用户隔离。
- 生成失败要显式提示：文档、PPT、视频等生成链路收到模型额度、服务配置、网络或工具错误时，前端弹窗提示联系项目负责人，不再静默失败。
- 学习伙伴支持直接对话：学习伙伴页面新增“直接对话 / 任务模式”，直接对话调用后端大模型接口；浏览器本机控制只在安装 SparkLearn 桌面端并启用本地服务后可用，线上 Web 版只支持对话、任务建议和资源处理。
- 接口暴露收紧：部署 nginx 会屏蔽常见敏感路径和扫描路径；AI 相关接口保留限流；跨域来源限制在正式域名和服务器 IP。

上线前推荐顺序：先备份服务器数据与 `.env.deploy`，再上传代码，随后执行 `docker compose -f docker-compose.deploy.yml build` 和 `docker compose -f docker-compose.deploy.yml up -d`，最后验证 `/health`、登录注册、多用户空状态、演示账号数据、容器内 `ffmpeg -version`。

当前主分支以 `feature/webpage-text-ingest-plugin` 为准完成同步。本轮重点是把“外部网页资料采集”和“小程序轻量学习体验”做成可直接使用的产品闭环。

### 本轮 Tutor A2UI / AG-UI 更新

- Tutor 对话接入 A2UI 自动界面能力：A2UI 不再作为手动模式按钮出现，而是由后端根据学习计划、任务安排、任务卡、本周/今日学习等意图自动触发。
- 个性化行动面板升级：当用户提出学习安排类需求时，助手可以直接输出个性化学习行动面板，展示画像依据、推荐下一步、资料/练习/视频等多模态任务入口。
- AG-UI 调用过程可视化：`/api/tutor/chat` 在 SSE 流中新增 `agui` 事件，用于展示运行过程、步骤状态、工具调用参数和结果。
- 画像优先链路固定：每次 Tutor 知识问答调用过程的第一步固定为“加载学习画像”，并通过 `load_student_profile` 展示阶段、薄弱点、学习偏好和可用时间。
- 过程面板可折叠：A2UI 结果面板下方显示 AG-UI 调用过程，默认展开画像加载步骤，其余步骤可按需展开查看。
- 加载态补齐：A2UI 面板或 AG-UI 事件尚未返回时，前端会显示动画骨架占位，避免对话区域空白等待。
- 兼容历史消息：助手消息会保存并恢复 `a2ui_events` 与 `agui_events`，刷新会话后仍能看到个性化面板和调用过程。

- 教学、社区、移动端和本机工具不再是孤立模块，而是可以互相导流的产品面。
- 后续无论是接入新的 AI 能力、扩展新的内容形态，还是增强本地工具链，都可以在现有矩阵上继续生长。

## 核心能力

### 1) 对话式学习画像

通过自然语言互动采集学习者知识基础、认知偏好、薄弱点与学习目标，持续更新画像，降低传统问卷成本。

- 输入：首次访谈、学习行为、练习结果、资源使用偏好。
- 输出：能力分层、知识图谱掌握度、风险点、阶段目标。
- 价值：从“统一学习任务”切换为“因人而异的学习计划”。

### 2) 动态学习路径规划

基于画像、学习行为与练习反馈自动调整学习路径，确保任务难度与学习节奏匹配。

- 路径机制：目标拆解 -> 阶段任务 -> 每日行动建议。
- 调整机制：正确率、完成时长、卡点频率触发难度和节奏调整。
- 价值：减少“跟不上”或“重复刷题”导致的学习损耗。

### 3) 个性化资源生成

围绕当前学习节点生成文档、思维导图、题目、视频、播客等内容，并支持复用与迭代。

- 生成类型：知识讲解、练习题、案例、复习卡片、音视频内容。
- 生成策略：按画像中的薄弱点与目标优先级定向生产。
- 资源工作台：生成后的资源进入统一资源库，支持筛选、搜索、预览、下载、笔记和继续讲解。
- 价值：让“资源供给”从手工搜集升级为自动化、可迭代供给，并真正沉淀为后续学习资产。

### 4) 智能辅导与多角色协同

支持不同教学风格角色切换、AI 协同研讨、知识库增强答疑与语音交互。

- 角色能力：讲解型、启发型、督学型等教学风格切换。
- 交互方式：文本对话、语音输入、语音播报、知识库检索增强。
- 对话体验：长消息流支持自动跟随、脱离跟随识别和一键回到最新消息。
- 自动界面：学习计划、任务安排、任务卡等场景会自动触发 A2UI 个性化行动面板，不需要用户切换模式。
- 过程可视化：AG-UI 时间线展示画像加载、意图分析、面板同步等调用步骤，并支持折叠查看参数与结果。
- 价值：将“问答工具”升级为“可持续陪伴的学习伙伴”。

### 5) 过程评估与反馈闭环

将行为数据、练习结果与资源使用数据沉淀为学习报告，反哺后续学习策略。

- 评估维度：掌握度、稳定性、学习效率、阶段目标完成率。
- 反馈形式：阶段报告、错因分析、下一步学习建议。
- 价值：形成“学习-评估-优化”的持续闭环。

### 6) 学习发现与外部内容沉淀

系统支持从视频、代码仓库、技术文章和论文等外部来源发现学习资料，并把它们持续沉淀回学习资源体系。

- 发现入口：`/info-stream` 已升级为“学习发现”页面。
- 内容来源：B站、GitHub、论文和技术文章等外部内容源。
- 沉淀机制：外部内容可直接导入“我的资源”，以 `discovery` 类型统一管理。
- 价值：把“外部搜索”从一次性浏览行为变成可持续复用的学习资产入口。

### 7) RAG 与文本向量化检索

知识问答链路已具备向量化检索能力，支持从知识文件分片中召回高相关证据片段。

- 向量化能力：Embedding（query/para）文本向量化。
- 检索能力：知识分片召回 + 上下文拼接。
- 目标：减少纯拼接回答，提高知识问答准确性与可解释性。

### 8) 记忆系统与多轮上下文

系统具备多层记忆存储与召回能力，用于支持连续学习对话与个体化辅导。

- 记忆层：working / episodic / semantic / perceptual。
- 能力：记忆写入、检索、压缩整合、遗忘清理。
- 目标：降低多轮对话信息丢失，提升连续性与个体化。

### 9) 可信回答与防幻觉机制

已接入可信回答控制思路，在知识问答场景中增强证据约束与可信度表达。

- 机制：检索证据优先、回答约束、可信度反馈。
- 场景：知识问答、学习指导、引用证据类回答。
- 目标：降低幻觉风险，提升回答可验证性与教学可信度。

### 10) 多模态对话链路

Tutor 场景已支持文本主链路与图片生成链路并行存在，并进行流程隔离。

- 形态：文本问答 + 图像生成。
- 策略：图片生成链路与可信问答链路解耦，避免互相干扰。
- 目标：在保证稳定性的前提下提供多模态学习体验。

### 11) 本地工具扩展与 MCP 能力装配

平台支持通过 MCP 把外部工具服务和本地工具链接入 Tutor 学习空间，形成可扩展的学习工作台。

- 接入方式：同时支持远程 HTTP MCP 和本地 stdio MCP。
- 配置入口：学习空间内有 MCP 商店，桌面端可直接接入本地 stdio。
- 装配范围：搜索、文件系统、知识处理、外部服务调用等能力都可接入。
- 价值：Tutor 不再只是聊天窗口，而是可持续扩展的学习执行界面。

### 12) 桌面端应用（Electron）

SparkLearn 提供 Windows 桌面端应用，基于 Electron 将前端与后端服务统一托管在用户本机，无需远程部署即可完整体验平台全部功能。

- 启动方式：一键启动后端 (FastAPI) 与前端 (Next.js)，自动加载桌面窗口。
- 运行架构：前后端仅监听 `127.0.0.1`，数据不出本机，保障隐私安全。
- 开发支持：提供 `doctor` 环境检测、日志管理、健康检查与进程守护等完整工具链。
- 打包分发：支持 `electron-builder` 打包为 NSIS 安装程序（Windows）。
- 配置入口：桌面端提供本地配置入口，可维护本地模型、渠道和本地能力接入参数。
- 价值：降低部署门槛，让师生无需技术背景即可快速上手使用。

### 13) 平台管理端

提供独立的管理后台，支持平台运营、用户管理、内容审核与系统运维。

- 管理能力：平台总览看板、用户与权限管理、帖子内容审核、审计日志追踪、系统设置。
- 快捷入口：支持从管理端直接跳转教师端与数据大屏。
- 响应式设计：适配桌面端与小屏设备，侧栏自动折叠，操作体验流畅。
- 价值：为平台运营者提供集中化管理入口，降低运维成本。

### 差异化亮点补充

以下能力是当前版本里更有识别度、但之前 README 没有展开说明的部分。

#### 1. 桌面端本地化部署不是“壳”，而是本机能力接入层

SparkLearn Desktop 不只是把网页包进 Electron，而是负责把本地前端、本地后端和本机能力统一托管起来。

- 本机启动：桌面端统一拉起 `frontend` 和 `backend`，并做健康检查与日志托管。
- 本地监听：服务默认监听 `127.0.0.1`，避免把学习数据暴露到公网。
- 本机能力承接：凡是需要访问本地文件、启动本地命令、接入本机 MCP、运行本地 Agent 的场景，都由桌面端接管。
- 用户体验：用户不用手动配前后端环境，也不用单独理解本机服务编排。

这意味着 SparkLearn 的桌面端不是“另一个端”，而是平台的本地运行层。

#### 2. 学习空间里的 MCP 商店支持“远程 HTTP + 本地 stdio”双模式

当前 `/tutor/mcp-store` 不是简单的接口配置页，而是一个把 MCP 接入方式拆清楚的能力装配入口。

- HTTP MCP：适合远程服务，直接配置 URL、认证和请求头。
- stdio MCP：适合本地工具链，直接配置 `command`、`args_json`、`env_json`。
- 桌面端放开：在 SparkLearn 桌面端里，本地 `stdio MCP` 可以直接创建、保存和测试。
- 浏览器版收口：普通浏览器环境不接管本机进程，因此仍提示用户切换到桌面端完成本机接入。

这个设计把“网页负责可视化配置”和“桌面端负责本机执行边界”分开了，避免了把本机命令执行错误地塞进浏览器上下文。

#### 3. 学习发现和资源中心已经形成真实联动

这一轮里，外部内容发现不再停留在“搜索结果列表”，而是已经并入学习闭环。

- 学习发现页可以直接检索视频、代码仓库、论文和技术文章。
- 发现到的内容可以一键加入“我的资源”。
- 资源中心新增 `discovery` 类型，支持统一管理、预览和后续学习动作。
- Tutor 与资源类型系统同步识别 `discovery`，后续可以继续接到笔记、讲解和任务流里。

这意味着 SparkLearn 开始把“外部信息获取”从旁路工具，转成可沉淀的学习资产入口。

#### 4. 资源中心从“生成结果堆叠”转向“资源工作台”

原来的资源页更偏生成链路展示；现在的资源中心已经更接近真正的学习资源工作台。

- 支持按类型筛选和关键词搜索。
- 支持折叠左侧资源列表，把更多空间留给预览区。
- 不同资源类型拥有更明确的图标、摘要和操作语义。
- 视频、播客、文档、代码、学习发现资源的预览逻辑开始分化，而不是统一用同一块文本容器承载。

这一步的价值在于，平台不再只强调“能生成”，而是开始强调“生成后的资源怎么被继续学习和复用”。

#### 5. 本地 MCP 默认可用，不强制上锁

桌面端本地 MCP 配置默认采用“本地正常使用优先”的策略，而不是先把能力锁死再要求用户绕路。

- 默认保留本地 `exec` 能力。
- 默认不强制启用沙箱。
- 默认不强制 `restrictToWorkspace`。
- 需要更严格控制时，再由用户按实际部署要求开启限制。

这更符合当前 SparkLearn 的使用场景：教学演示、课程共创、本机知识处理、本地资源编排，优先保证能力能接起来，再逐步增加约束。

#### 6. MCP 不再是独立“插件页”，而是学习空间的能力扩展层

MCP 在 SparkLearn 里不是孤立的开发者功能，而是给 Tutor 学习空间持续扩展工具能力的接口层。

- 对 Tutor：可以接入搜索、文件系统、知识处理、外部工具服务。
- 对课程设计：可以把特定学科或任务链条需要的工具能力按需装配。
- 对后续联动：MCP 可以继续接到学习画像、知识库、任务流和资源生成链路里。

这让 Tutor 工作区从“对话界面”升级成“可装配、可扩展的学习工作台”。

#### 7. Tutor 工作区开始补足长对话使用体验

这次虽然不是重做 Tutor，但已经在高频使用细节上开始补体验。

- 长消息流支持自动跟随和脱离自动跟随状态识别。
- 当用户滚离底部时，会出现“回到最新消息”按钮。
- 新消息到来时，不再粗暴强制打断用户当前阅读位置。
- Agent 摘要结果支持新的 `answer` 结构，能承接更自然的网页总结输出。

这类改动不显眼，但直接影响 Tutor 是否能承接真正长时、多轮、信息密度较高的学习过程。

#### 8. 配置入口开始从“开发者视角”转向“用户可操作视角”

这一轮调整里，配置能力不再只停留在 JSON 和后端接口，而是开始进入用户可见的产品界面。

- 主平台内有明确入口进入本地配置。
- 学习空间内可以直接区分 HTTP MCP 和本地 stdio MCP。
- 文档页和配置页一起对齐，减少“页面能点但用户不知道怎么接”的落差。

这一步的价值不在于“加了一个表单”，而在于把原本只适合开发者手改配置文件的能力，转成了普通使用者也能理解的接入流程。

- Agent API（`/api/agent`）：学习宠物、任务发起与任务状态查询，以及网页摘要、搜索规划、对比与推荐等链路。
- MCP API（`/api/mcp`）：插件商店相关接口与工具接入入口，支持 `http` 与 `stdio`。
- Info Stream API（`/api/info-stream`）：外部内容发现、来源管理、收藏、资源导入。
- Video/Voice API：`/api/video`、`/api/voice-admin`。
- Memory API（`/api/memory`）：记忆读写、检索、整理、遗忘。
- Knowledge/RAG API（`/api/knowledge`）：知识文件、分片检索、上下文召回。

## 快速开始

### 环境要求

- Node.js 18+
- Python 3.11+

### 1) 启动后端

```bash
cd backend
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

### 2) 启动前端

```bash
cd frontend
npm install
npm run dev
```

访问：`http://localhost:3000`

### 3) 启动桌面端（可选）

```bash
cd desktop
npm install
npm run doctor   # 环境检测
npm run dev      # 一键启动桌面应用
```

桌面端会自动按顺序启动后端 → 前端 → 加载桌面窗口，无需手动执行步骤 1 和 2。

### 4) 说明

- 当前默认以 `single_user_id` 模式进行本地体验与联调。
- 面向多用户线上部署时，建议补齐鉴权、权限、审计与数据库迁移方案。
