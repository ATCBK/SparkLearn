# Universal PPT Prompt Design Skill

> 目标：把任意项目、任意主题、任意行业的内容，转化为**可复用、可扩展、排版匹配内容逻辑**的高质量 PPT 生成提示词。  
> 核心原则：**先判断内容类型，再选择版式结构，最后输出提示词。不要把所有内容硬塞进同一种模板。**

---

## 1. Skill 适用范围

本 Skill 适用于以下场景：

- 产品发布会 PPT
- 项目路演 PPT
- 商业计划书 PPT
- 科研项目展示 PPT
- 技术架构汇报 PPT
- 课程/教学展示 PPT
- 工作总结/复盘 PPT
- 比赛答辩 PPT
- 方案汇报 PPT
- 品牌介绍 PPT
- 案例展示 PPT
- 数据分析报告 PPT
- 政企/学校/企业宣传 PPT

无论输入内容是什么，都不要直接套固定版式，而是先识别页面内容的表达任务。

---

## 2. 核心工作流

### Step 1：理解用户目标

先判断用户最终想要什么：

- 是要做正式汇报？
- 是要做产品发布？
- 是要做比赛答辩？
- 是要做商业路演？
- 是要做技术架构讲解？
- 是要做学术科研展示？
- 是要做演示前的铺垫？
- 是要做结尾收束？

如果用户已经给出风格样例，应把样例当作**视觉参考**，但不能照搬内容结构。

---

### Step 2：拆分内容层级

对用户提供的文案进行结构化拆解：

1. 提取主标题
2. 提取副标题
3. 提取核心结论
4. 提取一级模块
5. 提取二级要点
6. 删除冗余解释
7. 保留必要因果关系
8. 保留关键数字、时间、金额、比例、模块数量、步骤数量
9. 判断是否需要拆成多页

判断标准：

- 一页只表达一个核心主题。
- 一页不要同时讲背景、方案、流程、优势、案例。
- 内容超过 5 个并列点，优先考虑拆页或转为结构化版式。
- 大段文字必须转为短句、标签、模块或流程节点。
- 结尾页不要堆信息，只做品牌收束或行动引导。

---

### Step 3：判断页面内容类型

每一页生成提示词前，必须先判断它属于哪种内容类型。

常见内容类型包括：

| 内容类型 | 表达任务 | 不适合的做法 | 推荐版式方向 |
|---|---|---|---|
| 封面页 | 建立品牌第一印象 | 堆功能、堆卖点 | 大标题 + 主视觉 + 标语 |
| 项目定位页 | 解释“是什么” | 放背景痛点 | 核心定义卡 + 价值标签 |
| 背景页 | 解释“为什么需要” | 直接讲产品功能 | 因果链 / 问题趋势 / 场景压迫感 |
| 痛点页 | 展示用户问题 | 普通三栏堆叠 | 三座大山 / 痛点地图 / 用户旅程断点 |
| 方案页 | 解释“怎么解决” | 抽象口号 | 输入-处理-输出 / 解决方案引擎 |
| 价值页 | 解释带来什么收益 | 五个卡片平铺 | 价值飞轮 / 价值雷达 / 收益闭环 |
| 亮点页 | 展示核心能力 | 六宫格散排 | 能力矩阵 / 蜂巢结构 / 中心辐射 |
| 流程页 | 展示步骤推进 | 文本列表 | 时间轴 / 轨道图 / 流水线 / 阶段图 |
| 架构页 | 展示系统结构 | 一堆模块漂浮 | 分层架构 / 中央编排 / 数据流向 |
| 模块页 | 展示功能组成 | 10 宫格堆卡 | 工具链地图 / 模块装配台 |
| 技术生态页 | 展示技术支撑 | 技术名词列表 | 技术底座 + 中央引擎 + 能力解析 |
| 团队页 | 展示协作能力 | 简历墙 | 能力线协同 / 角色战位 / 贡献矩阵 |
| 商业页 | 展示变现路径 | 四宫格商业模式 | 用户分层 + 商业引擎 + 变现路径 |
| 未来规划页 | 展示演进方向 | 普通待办列表 | 技术路线图 / 四轨光轨 / 里程碑 |
| 案例页 | 展示真实验证 | 截图乱贴 | 案例路径 + 结果卡 + 证据链 |
| 数据页 | 展示指标分析 | 大表格堆满 | 指标仪表盘 / 趋势图 / 对比矩阵 |
| 对比页 | 展示差异优势 | 两段文字 | 左右对照 / before-after / 竞品矩阵 |
| 结尾页 | 品牌收束 | 继续堆信息 | 极简标语 + 品牌主视觉 |

## 3. 版式选择规则

### 3.1 定义类内容

适合内容：

- 项目是什么
- 产品是什么
- 平台定位
- 核心概念
- 一句话介绍

推荐版式：

- 左侧核心定义卡 + 右侧概念图
- 中央品牌核心 + 周围关键词
- 主定义 + 三个价值标签
- 简洁产品说明 + 轻量流程图

避免：

- 把背景、痛点、优势全部塞进定位页
- 使用太多小卡片
- 让定义页变成说明书

---

### 3.2 痛点类内容

适合内容：

- 用户遇到的问题
- 行业瓶颈
- 当前流程阻力
- 使用前的困境

推荐版式：

- 三座大山
- 痛点地图
- 用户旅程断点
- 因果链
- 阻力漏斗
- 成本/效率/风险三角模型

避免：

- 普通三栏文字卡片
- 每个痛点写成长段
- 没有视觉隐喻

---

### 3.3 方案类内容

适合内容：

- 产品怎么解决问题
- 系统如何工作
- 解决方案组成
- 输入输出逻辑

推荐版式：

- Input → Engine → Output
- 用户需求 → 平台处理 → 成果交付
- 解决方案中枢
- 自动化流水线
- 三段式处理流程

避免：

- 只写功能列表
- 缺少产品处理逻辑
- 没有输入和输出

---

### 3.4 流程类内容

适合内容：

- 多步骤执行过程
- 时间顺序
- 工作流
- 操作路径
- 阶段规划

推荐版式：

- 横向时间轴
- 轨道式流程图
- 地铁线路图
- 四阶段执行看板
- 环形闭环流程
- 阶梯式推进

选择规则：

- 步骤少于 5 个：用横向流程
- 步骤 5–8 个：用阶段式流程
- 步骤超过 8 个：先分阶段，再做轨道图
- 如果上一页已经用时间轴，下一页不要继续用时间轴，可改为 2×2 阶段看板

---

### 3.5 架构类内容

适合内容：

- 系统架构
- 技术架构
- 平台组成
- 模块依赖
- 数据流转

推荐版式：

- 分层架构栈
- 左侧能力层 + 中央编排核心 + 右侧输出流
- 技术底座 + 服务层 + 应用层
- 中央 Orchestrator + 周边模块
- 数据流管线图

避免：

- 模块随机漂浮
- 技术名词堆成列表
- 架构层级不清楚

---

### 3.6 模块类内容

适合内容：

- 产品模块
- 功能组成
- 子系统
- 插件/工具链
- 能力库

推荐版式：

- 三段式模块装配台
- 工具链地图
- 中央平台 + 周边模块
- 模块分组矩阵
- 能力地图

规则：

- 先按任务阶段分组
- 每组 2–5 个模块最清晰
- 模块多时不要做大宫格，优先分区

---

### 3.7 技术生态类内容

适合内容：

- 技术栈
- 云生态
- GPU 生态
- 第三方能力融合
- 框架、模型、服务集成

推荐版式：

- 技术底座 + 中央产品引擎 + 能力解析
- 展示台 + 2×3 技术卡片
- 核心平台 + 生态环绕
- 算力基座 + 服务层 + 应用结果

注意：

- 技术生态页需要体现“支撑关系”，不要只列名词
- 如果用户要求“有台子”，主视觉应使用展示台/底座/产品平台
- 局部品牌色只能点缀，不能破坏全局主色

---

### 3.8 团队类内容

适合内容：

- 团队分工
- 成员贡献
- 项目协作
- 角色说明

推荐版式：

- 中央项目交付台 + 能力线汇聚
- 五人角色战位图
- 上方角色定位 + 下方贡献矩阵
- 协作网络图
- 职能泳道图

避免：

- 真人照片墙
- 简历式堆叠
- 每个人一大段文字

---

### 3.9 商业类内容

适合内容：

- 商业计划
- 商业模式
- 市场定位
- 目标用户
- 变现路径

推荐版式：

- 目标用户分层地图 + 商业化引擎 + 变现路径
- 用户群体 → 产品服务 → 收入模式
- 市场价值闭环
- 商业生态地图

避免：

- 虚构市场规模和收入数据
- 四宫格商业计划书模板感
- 过度商业广告化

---

### 3.10 结尾类内容

适合内容：

- 最后一页
- 品牌收束
- 过渡到现场演示
- 谢幕页

推荐版式：

- 极简品牌名 + 核心标语
- 品牌主视觉 + 一句话
- 产品展示台 + Live Demo 提示
- 大面积留白

避免：

- 继续堆功能
- 展示大量成果
- 普通“谢谢观看”
- 把结尾页做成总结报告页

---

## 4. 全局风格适配框架

生成任何 PPT 提示词前，都要先建立风格变量。

### 4.1 风格变量

```text
项目名称：{ProjectName}
页面编号：{PageNumber}
页面主题：{PageTheme}
页面类型：{PageType}
视觉风格：{VisualStyle}
主色调：{PrimaryColors}
辅助色：{AccentColors}
字体气质：{TypographyMood}
主视觉类型：{HeroVisual}
背景元素：{BackgroundElements}
禁用元素：{ForbiddenElements}
```

### 4.2 常见风格模板

#### 亮色科技发布会风

- 主色：白色、浅灰、冰蓝、淡青色
- 特征：玻璃拟态、轻量 3D、柔光、数据线、圆弧、科技网格
- 适合：AI 产品、科研工具、SaaS、教育科技、硬科技路演

#### 深色科技发布会风

- 主色：深蓝、黑色、青色、电光蓝
- 特征：高对比、发光线条、粒子、暗色空间
- 适合：安全、底层技术、算力平台、游戏科技、开发者大会

#### 政企白皮书风

- 主色：白色、深蓝、灰色
- 特征：规整、克制、线条、表格、严肃
- 适合：政府项目、企业方案、正式申报

#### 商业路演风

- 主色：白色、蓝色、紫色、渐变色
- 特征：数据感、增长曲线、市场地图、商业闭环
- 适合：创业项目、融资、商业计划

#### 教育培训风

- 主色：白色、浅蓝、绿色、橙色
- 特征：亲和、轻插画、学习路径、知识地图
- 适合：课程、学习平台、教育产品

#### 学术科研风

- 主色：白色、蓝灰、深蓝
- 特征：论文、图表、公式、实验矩阵、数据可视化
- 适合：科研平台、论文汇报、实验项目

## 6. 页面生成前的自检清单

每次输出提示词前，都要检查：

### 内容匹配

- 这一页到底要讲什么？
- 是否只讲一个主题？
- 是否需要拆页？
- 是否有关键数字要突出？
- 是否有因果、流程、层级、对比或并列关系？

### 版式匹配

- 当前版式是否贴合内容类型？
- 是否和上一页重复？
- 是否有明确视觉中心？
- 是否有清晰阅读路径？
- 是否避免了普通卡片堆叠？

### 视觉匹配

- 是否延续全套风格？
- 是否有足够留白？
- 是否颜色统一？
- 是否图标风格统一？
- 是否背景不抢内容？

### 专业度检查

- 是否像正式 PPT，而不是海报拼贴？
- 是否避免大段文字？
- 是否避免元素散乱？
- 是否避免过度装饰？
- 是否符合用户给的参考图气质？

## 7. 常见错误与修正策略

### 错误 1：所有页面都用三栏卡片

问题：显得模板化、廉价、缺少专业排版。

修正：

- 痛点页用三座大山
- 方案页用输入-引擎-输出
- 流程页用轨道式流程
- 架构页用分层架构
- 价值页用价值飞轮
- 结尾页用极简品牌收束

---

### 错误 2：内容很多但不拆页

问题：页面拥挤，观众无法阅读。

修正：

- 超过 5 个大点，考虑拆页
- 超过 8 个步骤，必须分阶段
- 超过 10 个模块，必须分组
- 团队成员超过 4 个，使用矩阵

---

### 错误 3：只关注风格，不关注版式

问题：画面漂亮但信息逻辑混乱。

修正：

- 先判断内容类型
- 再选择版式
- 最后写风格提示
- 任何视觉元素都要服务内容逻辑

---

### 错误 4：结尾页继续堆信息

问题：收束失败，观众记不住主题。

修正：

- 最后一页只保留品牌名、标语、轻量主视觉
- 需要演示时只放“Live Demo Starts Now”
- 不放成果列表，不放功能清单

---

### 错误 5：参考图只照搬样式

问题：参考图适合别的内容，但不一定适合当前页面。

修正：

- 参考图只提取构图、节奏、视觉气质
- 内容表达结构必须重新设计
- 如果参考图有“台子”，可以迁移为产品展示台
- 如果参考图是“功能解析”，可以迁移为能力解析区

## 8. 通用版式库

### 8.1 高级感版式

- 中央产品展示台
- 玻璃拟态信息面板
- 主视觉 + 功能解析区
- 中央引擎 + 环绕节点
- 分层能力塔
- 价值飞轮
- 四轨路线图
- 目标用户分层地图
- 技术底座 + 产品核心
- 极简品牌结尾页

### 8.2 逻辑表达版式

- 输入 → 处理 → 输出
- 问题 → 原因 → 结果
- 当前 → 方案 → 未来
- 底座 → 核心 → 应用
- 用户 → 场景 → 价值
- 能力 → 机制 → 产物
- 阶段 → 任务 → 交付
- 目标 → 路径 → 指标

### 8.3 对比表达版式

- Before / After
- 传统方式 vs 新方案
- 用户痛点 vs 产品能力
- 国内 vs 国外
- 当前状态 vs 未来状态
- 竞品对比矩阵

### 8.4 数据表达版式

- 指标仪表盘
- 趋势折线
- 对比柱状
- 雷达图
- 数字卡片组
- 关键指标瀑布图
- 指标闭环图

### 8.5 流程表达版式

- 横向时间轴
- 竖向里程碑
- 环形闭环
- 轨道式流程
- 地铁线路图
- 泳道图
- 阶梯式路径
- 四阶段看板

## 9. 通用提示词模板

下面模板可以复制给任何项目使用。

```markdown
请根据我提供的页面内容，先判断这一页的内容类型，再选择最贴合内容逻辑的 PPT 版式，最后输出可直接用于 AI 出图或 PPT 设计的完整提示词。

要求：
1. 不要固定套用三栏卡片或普通宫格。
2. 每页都要根据内容选择合适版式。
3. 先说明版式判断：这一页属于什么内容，为什么选择该版式。
4. 再输出完整生成提示词。
5. 提示词要包含：页面比例、整体风格、主色调、标题区、主体布局、视觉元素、背景元素、文案内容、排版要求、避免事项。
6. 页面要有明确视觉中心、清晰阅读路径、充足留白和统一风格。
7. 不要让页面信息散乱，不要堆长段文字。
8. 如果是最后一页，优先做品牌收束页，不要继续堆信息。
```

## 10. 当前对话样例沉淀

本次 PaperFlow 项目只是一个样例，不应把 Skill 固定到 PaperFlow。可复用经验如下：

### 样例中的关键经验

1. 用户先给出封面参考风格。
2. 初始提示词偏普通，后续用户指出版式要匹配内容。
3. 修正后建立了“先判断内容类型，再选版式”的规则。
4. 第 4 页用户痛点页从普通三卡片改成“三座大山”。
5. 第 5 页产品方案页采用“输入 → PaperFlow 引擎 → 输出”。
6. 第 8 页流程页采用“四阶段轨道式流程图”。
7. 第 11 页技术架构页采用“七层架构栈 + 编排核心 + 产物流转面板”。
8. 第 13 页 NVIDIA 生态页结合参考图，改为“产品展示台 + 下方能力解析”。
9. 最后一页从成果堆叠页改成极简品牌收束页。
10. 整个流程最终沉淀为通用方法：**内容类型决定版式，风格统一但结构不重复。**

### 可以复用的全局原则

- 不要一上来就写提示词。
- 先判断这一页的表达任务。
- 版式必须服务内容。
- 每页要和上一页有差异。
- 风格统一，结构变化。
- 结尾页要收束，不要继续展开。
- 参考图不是模板，是构图灵感。
- 信息越复杂，越需要结构化，而不是堆卡片。

## 11. 最终执行准则

生成 PPT 提示词时，始终遵守以下顺序：

```text
用户内容
↓
判断页面类型
↓
判断信息关系：并列 / 递进 / 流程 / 对比 / 层级 / 闭环 / 证明
↓
选择最匹配的版式
↓
匹配全局视觉风格
↓
压缩页面文案
↓
写完整提示词
↓
自检是否专业、清晰、有视觉中心
```

一句话总结：

> **不要为了好看而排版，要为了表达清楚而设计；当版式贴合内容逻辑时，页面自然会显得专业。**
